# Reproductor 360 WebXR para Meta Quest — Plan de Implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reproducir video 360 equirectangular mono en un Meta Quest, sirviendo una página WebXR desde la app Elixir video-repo, sin APK ni modo desarrollador.

**Architecture:** Se agrega un listener HTTPS a la app Elixir existente (WebXR exige contexto seguro) y una ruta `/vr` que sirve una página con Three.js. La página lista los videos marcados con sufijo `_360`, y al elegir uno monta el `<video>` como textura sobre una esfera invertida dentro de una sesión `immersive-vr`. El listener HTTP existente queda intacto.

**Tech Stack:** Elixir 1.17, Plug 1.16, Bandit 1.5, ExUnit + Plug.Test, Three.js r160 (build UMD), WebXR Device API, k3s.

## Global Constraints

- **No hay Elixir en la laptop ni en el host del nodo.** El único Elixir disponible es el de la imagen `elixir:1.17-slim` del pod. **Todas las pruebas se corren con `scripts/test-in-pod.sh`**, que manda el fuente por un pipe de tar al pod y ejecuta ahí. Nunca invocar `mix` directamente: no existe.
- **`mix test` a secas rompe.** `mix.exs` declara `mod: {Videorepo.Application, []}`, así que arrancar la app durante las pruebas intenta bindear el puerto 4000 — ocupado por el servidor de producción en ese mismo pod — y la corrida entera muere con `:eaddrinuse`. Por eso el runner usa `--no-start`. Las pruebas llaman al router directamente y no necesitan sockets.

- **El HTTP en el puerto 4000 → NodePort 30080 no se toca.** La TV Noblex reproduce desde `http://<ip-del-nodo>:30080/videos/x.mp4`. El HTTPS entra como listener adicional, nunca como reemplazo.
- **La app debe arrancar aunque falten los certificados.** Si el cert no está, se omite el child de HTTPS y el HTTP sigue sirviendo.
- **Three.js versión exacta: `0.160.0`, archivo `build/three.min.js`.** Es la última versión con build UMD autocontenido; r169 lo eliminó y r180 parte el módulo en `three.core.js`. Va commiteado al repo, nunca desde un CDN.
- **Marcado de contenido 360: sufijo `_360` antes de la extensión** (`playa_360.mp4`). Sin cambios en la API.
- **Sin dependencias nuevas en `mix.exs`.** ExUnit y `Plug.Test` ya vienen con Elixir y Plug.
- **360 mono solamente.** Nada de estéreo top-bottom ni side-by-side.
- Rama de trabajo: `feat/quest-360-webxr`.

```javascript
'use strict';

// Un equirectangular y un video plano son ambos mp4: nada en el archivo los
// distingue de forma confiable. El sufijo _360 en el nombre es la marca.
function is360(name) {
  return /_360\.[^.]+$/i.test(name);
}

function filter360(videos) {
  return videos.filter(function (v) { return is360(v.name); });
}

window.VR360 = { is360: is360, filter360: filter360 };

var msgEl = document.getElementById('msg');
var listEl = document.getElementById('list');
var stageEl = document.getElementById('stage');
var videoEl = document.getElementById('video');

function human(b) {
  var u = ['B', 'KB', 'MB', 'GB', 'TB'], i = 0;
  while (b >= 1024 && i < u.length - 1) { b /= 1024; i++; }
  return b.toFixed(1) + ' ' + u[i];
}

function show(kind, html) {
  msgEl.className = kind;
  msgEl.innerHTML = html;
}

function clearMsg() {
  msgEl.className = '';
  msgEl.innerHTML = '';
}

function render(videos) {
  var only360 = filter360(videos);
  listEl.innerHTML = '';

  if (only360.length === 0) {
    show('info',
      'No hay videos 360 todavia. Se listan solo los archivos cuyo nombre termina en ' +
      '<code>_360</code> antes de la extension, por ejemplo <code>playa_360.mp4</code>. ' +
      'Subilos desde <a href="/" style="color:#2f81f7">la pagina principal</a> y renombralos con ese sufijo.');
    return;
  }

  clearMsg();
  only360.forEach(function (v) {
    var li = document.createElement('li');
    var b = document.createElement('button');
    b.className = 'pick';
    b.innerHTML = '<span>🌐 ' + v.name.replace(/[<>&]/g, '') + '</span>' +
                  '<span class="s">' + human(v.size) + '</span>';
    b.onclick = function () { select(v); };
    li.appendChild(b);
    listEl.appendChild(li);
  });
}

function select(v) {
  videoEl.src = '/videos/' + encodeURIComponent(v.name);
  listEl.style.display = 'none';
  stageEl.className = 'on';
}

function backToList() {
  videoEl.pause();
  videoEl.removeAttribute('src');
  videoEl.load();
  stageEl.className = '';
  listEl.style.display = '';
}

function load() {
  fetch('/api/videos')
    .then(function (r) {
      if (!r.ok) throw new Error('HTTP ' + r.status);
      return r.json();
    })
    .then(render)
    .catch(function (e) {
      show('err', 'No se pudo leer la lista de videos: ' + e.message +
        ' <button class="btn sec" onclick="location.reload()">Reintentar</button>');
    });
}

videoEl.addEventListener('error', function () {
  var err = videoEl.error;
  var names = { 1: 'ABORTED', 2: 'NETWORK', 3: 'DECODE', 4: 'SRC_NOT_SUPPORTED' };
  show('err', 'Fallo el video: ' + (err ? (names[err.code] || err.code) : 'desconocido') +
    '. Con material 4K un fallo de decodificacion es plausible.');
});

document.getElementById('back').onclick = backToList;

load();
```

```elixir
defmodule Videorepo.TLS do
  @moduledoc """
  Unica fuente de verdad sobre si el listener HTTPS puede levantarse.

  WebXR exige contexto seguro, asi que el reproductor 360 necesita HTTPS. Pero
  la TV Noblex reproduce por HTTP plano: si falta el certificado la aplicacion
  tiene que arrancar igual, sin HTTPS, en vez de caerse entera.
  """

  @spec options() :: {:ok, keyword()} | :disabled
  def options do
    dir = Application.get_env(:videorepo, :tls_dir, "/data/videos/.certs")
    cert = Path.join(dir, "cert.pem")
    key = Path.join(dir, "key.pem")

    if File.regular?(cert) and File.regular?(key) do
      {:ok, [certfile: cert, keyfile: key]}
    else
      :disabled
    end
  end
end
```

`File.regular?/1` y no `File.exists?/1`: un directorio llamado `cert.pem` haria explotar el listener al arrancar en vez de degradar limpio.

```elixir
defmodule Videorepo.Application do
  @moduledoc false
  use Application
  require Logger

  @read_timeout 300_000

  @impl true
  def start(_type, _args) do
    dir = Application.get_env(:videorepo, :video_dir, "/data/videos")
    File.mkdir_p!(dir)

    # Carpeta temporal para las subidas EN EL MISMO filesystem que el storage,
    # asi mover el archivo subido es instantaneo (rename) y no una copia.
    tmp = System.get_env("TMPDIR")
    if tmp, do: File.mkdir_p!(tmp)

    Supervisor.start_link(children(), strategy: :one_for_one, name: Videorepo.Supervisor)
  end

  @doc """
  Arbol de supervision. Publica para poder probar la composicion sin arrancar
  la aplicacion: el HTTPS es condicional y esa decision hay que poder verificarla.
  """
  def children do
    port = Application.get_env(:videorepo, :port, 4000)
    dir = Application.get_env(:videorepo, :video_dir, "/data/videos")

    Logger.info("videorepo escuchando en :#{port} — storage: #{dir}")

    [Videorepo.Jobs, http_child(port)] ++ https_child()
  end

  defp http_child(port) do
    Supervisor.child_spec(
      {Bandit,
       plug: Videorepo.Router,
       scheme: :http,
       port: port,
       # read_timeout amplio: subidas grandes por WiFi no se cortan por inactividad
       thousand_island_options: [read_timeout: @read_timeout]},
      id: :videorepo_http
    )
  end

  defp https_child do
    case Videorepo.TLS.options() do
      {:ok, tls_opts} ->
        tls_port = Application.get_env(:videorepo, :tls_port, 4443)
        Logger.info("videorepo TLS escuchando en :#{tls_port} (WebXR necesita https)")

        [
          Supervisor.child_spec(
            {Bandit,
             plug: Videorepo.Router,
             scheme: :https,
             port: tls_port,
             thousand_island_options: [
               read_timeout: @read_timeout,
               transport_options: tls_opts
             ]},
            id: :videorepo_https
          )
        ]

      :disabled ->
        Logger.warning("sin certificado en TLS_DIR: arranco solo HTTP (la TV sigue funcionando)")
        []
    end
  end
end
```

```javascript
// ---------- reproductor WebXR ----------

var SPHERE_RADIUS = 500;

var renderer = null, scene = null, camera = null, xrSession = null;
var enterBtn = document.getElementById('enter');

function buildScene() {
  if (renderer) return;

  scene = new THREE.Scene();
  camera = new THREE.PerspectiveCamera(70, window.innerWidth / window.innerHeight, 0.1, 1100);

  // Esfera vista DESDE ADENTRO: escalar en -1 invierte las normales.
  var geo = new THREE.SphereGeometry(SPHERE_RADIUS, 60, 40);
  geo.scale(-1, 1, 1);

  var texture = new THREE.VideoTexture(videoEl);
  texture.colorSpace = THREE.SRGBColorSpace;

  scene.add(new THREE.Mesh(geo, new THREE.MeshBasicMaterial({ map: texture })));

  renderer = new THREE.WebGLRenderer({ antialias: true });
  renderer.setPixelRatio(window.devicePixelRatio);
  renderer.setSize(window.innerWidth, window.innerHeight);
  renderer.xr.enabled = true;
  renderer.xr.setReferenceSpaceType('local');
  renderer.domElement.style.display = 'none';
  document.body.appendChild(renderer.domElement);
  renderer.setAnimationLoop(function () { renderer.render(scene, camera); });

  // Gatillo = play/pausa. El boton del sistema del Quest cierra la sesion solo.
  var controller = renderer.xr.getController(0);
  controller.addEventListener('selectstart', togglePlay);
  scene.add(controller);
}

function togglePlay() {
  if (videoEl.paused) { videoEl.play(); } else { videoEl.pause(); }
}

function onSessionEnd() {
  xrSession = null;
  renderer.domElement.style.display = 'none';
  videoEl.pause();
  enterBtn.disabled = false;
  enterBtn.textContent = 'Entrar en VR';
}

function enterVR() {
  // navigator.xr solo existe en contexto seguro. Es de lejos el fallo mas
  // probable de todo esto, asi que el mensaje tiene que ser explicito.
  if (!navigator.xr) {
    show('err', 'No hay WebXR en este navegador. La causa habitual es haber entrado por ' +
      '<code>http://</code>: WebXR solo funciona sobre <code>https://</code>. ' +
      'Proba con <code>https://<ip-del-nodo>:30443/vr</code>.');
    return;
  }

  navigator.xr.isSessionSupported('immersive-vr').then(function (supported) {
    if (!supported) {
      show('info', 'Este dispositivo no soporta VR inmersiva. Podes ver el video plano aca abajo, ' +
        'pero para el 360 real hace falta el visor.');
      videoEl.controls = true;
      return;
    }

    buildScene();
    enterBtn.disabled = true;

    return navigator.xr.requestSession('immersive-vr', { optionalFeatures: ['local-floor'] })
      .then(function (session) {
        xrSession = session;
        session.addEventListener('end', onSessionEnd);
        renderer.domElement.style.display = '';
        return renderer.xr.setSession(session);
      })
      .then(function () {
        return videoEl.play();
      });
  }).catch(function (e) {
    enterBtn.disabled = false;
    show('err', 'No se pudo iniciar la sesion VR: ' + e.message);
  });
}

enterBtn.onclick = enterVR;

window.addEventListener('resize', function () {
  if (!renderer) return;
  camera.aspect = window.innerWidth / window.innerHeight;
  camera.updateProjectionMatrix();
  renderer.setSize(window.innerWidth, window.innerHeight);
});
```
